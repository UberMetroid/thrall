The problem it removes

Handing a team a synced share usually means installing a sync client on every laptop, sharing each folder by hand, and un-sharing everything by hand when someone leaves. Your directory already knows who works here and who no longer does — THRALL reads that and does the work for you.

What the person using it actually does

No account to create, no separate password, no sync client on the hub to babysit.

01Signs in with their work account

The portal binds directly to your LDAP or Active Directory server over RFC 4511.

Authentication is the directory's job. THRALL never stores a user password.

02Finds their folders already there

Standard folders and any custom folder are provisioned on the hub and bound to their devices.

Desktop, Documents, Music, Pictures, Videos — or a folder you named yourself.

03Gets access from one screen

An admin ticks a person against a team folder. It reaches every device that person owns within seconds.

Untick it and access is revoked everywhere — including the devices you cannot reach.

How a fleet is laid out

THRALL is the control plane, never a peer. It never bundles, installs, or spawns Syncthing. The peer — the thing that actually stores and replicates bytes — is stock Syncthing that you run on every hub that holds data.

    +----------------------------------------------+
    |         Control-plane host  (ONE per fleet)  |
    |                                              |
    |         [ thrall container ]                 |
    |           - RFC 4511 LDAP bind               |
    |           - self-service web portal          |
    |           - roster / folder topology / ACLs  |
    |           - reconciler: calls each peer's    |
    |             authenticated REST API           |
    |           - no SSH client, no SSH access     |
    +--------+---------------+---------------+-----+
             |               |               |
         REST API        REST API        REST API
        (loopback)       (tailnet)       (tailnet)
             |               |               |
             v               v               v
      +------------+  +------------+  +------------+
      |   hub-a    |  |   hub-b    |  |   hub-c    |
      | [ syncthing|  | [ syncthing|  | [ syncthing|
      |  container]|  |  container]|  |  container]|
      +------------+  +------------+  +------------+

One control plane per fleet, not one per hub. The roster is a single-writer store with no lock and no merge, and every control plane reconciles every hub listed in fleet.yaml. Running one per hub would mean N × N reconciliation writes racing into the same peers — a duplicated brain, not redundancy. For failover, run a warm standby: a second control plane holding a standby copy of the roster, promoted deliberately, never reconciling concurrently with the primary.

Every peer is reached over its own REST API, authenticated with that peer's API key. A peer sharing the host with the daemon is reached over loopback; every other peer publishes the same API on a reachable address. The peer creates its own folder paths, so the daemon never touches a peer's filesystem. There is no SSH anywhere in the path — not in the image, not in the configuration, and no fleet-wide credential that can reach every hub at once.

The peer is stock Syncthing that you run yourself. This project publishes no peer image and ships no peer unit: a peer is separate software, and THRALL only ever speaks to it over REST.

Why you can trust it with a directory server

THRALL holds an LDAP bind password and the access rules for every user's files. These are the claims we make — and the test that fails the build if a claim stops being true.

Get it running

One image, one unit, one configuration file. The peer is stock Syncthing that you run yourself — this project publishes no peer image.

# 1. The image (the peer is stock Syncthing, which this project does not ship)
sudo podman pull ghcr.io/ubermetroid/thrall:0.5.4

# 2. The directory bind password is a container secret, never a file
printf '%s' '<bind password>' | sudo podman secret create ldap_bind_password -

# 3. Deploy
sudo cp quadlet/thrall.container /etc/containers/systemd/
sudo systemctl daemon-reload
sudo systemctl enable --now thrall.service

Then point it at your directory, run a peer on every hub that stores files, and list those hubs in fleet.yaml. The README walks through it step by step, including how to run a peer and give each one its own API key.
